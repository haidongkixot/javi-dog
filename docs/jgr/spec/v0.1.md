# Javi Grande Rules (JGR) — v0.1 draft

- Status: **Draft** (S1b, 2026-10-20). Breaking changes are allowed until v1.0.
- Reference implementation: JD-M01 `@javis-dog/jgr-spec` (`packages/jgr-spec`). Conformance vectors: [`../conformance/vectors/`](../conformance/vectors/).
- Decision record: [ADR-0004](../../adr/0004-jgr-v0.1-envelope-and-transport.md). Research notes: [`../research/`](../research/).

The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are used as in RFC 2119 / RFC 8174.

## 1. Purpose and scope

JGR is the shared language between coding tools (Claude Code, Codex CLI, Gemini CLI, Cursor, GitHub, custom agents) and Javi's Dog. It carries **operational signals** — lifecycle, status, heartbeats, token/cost deltas, attention requests — so the platform can build a trustworthy operating picture. It is optimized for three properties, in this order:

1. **Privacy** — the default payload contains no prompts, source code, paths or secrets.
2. **Reliability** — at-least-once delivery with deterministic deduplication and gap detection.
3. **Speed** — small events, batched, gzip-compressed; delivery target p95 < 2 s *(hypothesis, to be measured in S5)*.

Out of scope for v0.1: commands from the platform back to agents, token/credit exchange (Pack Pool), and transcript storage.

## 2. Roles

- **Producer** — a collector, hook script, SDK or MCP server that emits events. Identified by a stable `producer_id` per installation.
- **Receiver** — the Javi's Dog ingest gateway (JD-M05).
- **Thread** — one coding session in one tool (`thread_ref`). **Agent** — a main agent or subagent inside a thread (`agent_ref`).

## 3. Event envelope

```json
{
  "jgr": "0.1",
  "event_id": "01JBZ4XQ80000000000000001A",
  "producer_id": "prod_claude-code_7f3a",
  "project_ref": "javis-dog-web-app",
  "thread_ref": "sess_2b9c",
  "agent_ref": "agent_architect",
  "sequence": 42,
  "type": "heartbeat",
  "status": "working",
  "occurred_at": "2026-10-20T18:59:30Z",
  "usage_delta": { "input_tokens": 1280, "output_tokens": 462, "model": "claude-opus-5-5", "estimated": false },
  "privacy_class": "L0",
  "attributes": { "platform": "claude-code", "tool_name": "Edit" }
}
```

| Field | Req. | Rule |
|---|---|---|
| `jgr` | MUST | Protocol version, exactly `"0.1"` (JGR-R01) |
| `event_id` | MUST | ULID or UUID, unique per event; the deduplication key (JGR-R02) |
| `producer_id` | MUST | Stable per installation; opaque (JGR-R03) |
| `project_ref` | MUST | Project slug or ID registered in Javi's Dog |
| `thread_ref` | MUST | Opaque session identifier; hashed or random, never a path |

All `*_ref` and `producer_id` values are **opaque identifiers** matching `^[A-Za-z0-9_:-]{1,128}$` — no `/`, `.` or `@`, so file paths, file names and email addresses are rejected (`schema`). *(Tightened on 2026-10-20 after the G1 Guru review.)*
| `agent_ref` | MAY | Opaque agent identifier within the thread |
| `sequence` | MUST | Non-negative integer, strictly increasing per (`producer_id`, `thread_ref`) (JGR-R06) |
| `type` | MUST | A core type (§4) or an extension `x.<vendor>.<name>` (JGR-R04) |
| `status` | cond. | REQUIRED for `heartbeat`, `agent.started`, `agent.stopped` (JGR-R05) |
| `occurred_at` | MUST | RFC 3339 timestamp with offset, producer clock (JGR-R07) |
| `usage_delta` | cond. | REQUIRED for `usage.reported` (JGR-R08) |
| `privacy_class` | SHOULD | `L0` (default), `L1`, `L2` (JGR-R09) |
| `attributes` | MAY | ≤ 16 keys; values string (≤ 128 chars), number or boolean; allowlisted per class |
| `encrypted` | cond. | REQUIRED iff `privacy_class` is `L2` (JGR-R10) |

Unknown top-level fields MUST be rejected (JGR-R11): a receiver never silently stores data it did not agree to receive.

## 4. Event types (JGR-R04)

| Type | Meaning |
|---|---|
| `session.started` / `session.ended` | Thread lifecycle |
| `agent.started` / `agent.stopped` | Main agent or subagent lifecycle (status required) |
| `heartbeat` | "Still alive", with current status (status required) |
| `task.started` / `task.completed` / `task.failed` | Unit of work (tool call, plan step, test run) |
| `attention.requested` | The thread waits for a human (approval, question) |
| `usage.reported` | Token / cost delta (usage_delta required) |
| `error` | Producer- or tool-level error (use `attributes.error_code`) |

Extensions use `x.<vendor>.<name>`; receivers MUST accept and store them without interpreting them.

## 5. Status and freshness (JGR-R05)

`status` ∈ `working`, `waiting`, `idle`, `blocked`, `failed`, `completed`. **`stale` MUST NOT be sent**: the receiver derives it when no event arrives for a thread within its freshness window (default: 3 × the producer's heartbeat interval; producers SHOULD send a heartbeat at least every 60 s while working). This implements the brand rule *Live means verified*.

## 6. Usage deltas (JGR-R08)

`usage_delta` carries counters **since the producer's previous report for the same thread**: `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `reasoning_tokens` (non-negative integers), `cost_usd` (non-negative number), `model`, and `estimated` (default `false`). At least one counter MUST be present. Deltas, not totals, make duplicates harmless after deduplication and keep events small. A producer that cannot read exact counts MUST set `estimated: true`.

## 7. Privacy classes (JGR-R09, R10)

| Class | Allowed content | Enforcement |
|---|---|---|
| **L0** (default) | Operational metadata only. Attribute allowlist: `platform`, `platform_version`, `collector_version`, `provider`, `model`, `tool_name`, `task_kind`, `duration_ms`, `exit_code`, `error_code`, `retry_count`, `attempt`, `context_used_ratio`, `budget_remaining_ratio` | Any other attribute → `privacy_forbidden_attribute` |
| **L1** | L0 + hashed identifiers `repo_hash`, `branch_hash`, `file_hash`, `cwd_hash` as `sha256:<64 hex>` | Unhashed → `privacy_unhashed_identifier` |
| **L2** | L1 + an `encrypted` object `{ alg: "A256GCM", kid, iv, ciphertext }` (base64url), encrypted on the producer with a key the platform never sees | `encrypted` without L2 → `privacy_encrypted_requires_l2`; L2 without `encrypted` → `privacy_l2_requires_encrypted` |

Violations are **rejected, not stripped**, so producers learn about them. Prompts, source code, file contents, commands and secrets MUST NOT appear in any plaintext field in any class. Hashing in L1 SHOULD use a per-project salt so hashes cannot be matched across projects (key management lands with JD-M11 in S5).

## 8. Transport (JGR-R12, R13)

- `POST /api/v1/events` over HTTPS, body `{ "events": [ ... ] }`, `Content-Type: application/json`, optionally `Content-Encoding: gzip`.
- Limits: ≤ 100 events and ≤ 256 KB (uncompressed) per batch; ≤ 8 KB per event (target < 4 KB).
- Authentication: `Authorization: Bearer <project ingest token>` (scoped to one project, hashed at rest, rotatable — JD-M04, S2).
- Request signing is planned for **v0.2**: `JGR-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of "t.body">`, 300 s tolerance, constant-time comparison; RFC 9421 is the long-term path.
- A batch-level `Idempotency-Key` header MAY be sent; it is informative only (the IETF draft is not an RFC). Per-event `event_id` is the normative idempotency mechanism.
- Responses:
  - `202 Accepted` with `{ accepted, duplicates, rejected: [{ index, event_id, issues: [{ code, path, message }] }] }` — **partial acceptance** (R13): valid events are stored even if others fail.
  - `400` malformed batch · `401/403` token problems · `413` too large · `429` rate limited with `Retry-After` · `5xx` transient.
  - The reference receiver (JD-M05, ADR-0008) applies the 256 KB limit **after** gzip decompression, answers `401` with `WWW-Authenticate: Bearer` for missing, unknown or revoked tokens, deduplicates per project, and allows 60 batches per token per minute.
- Producers MUST retry `429` and `5xx` with exponential backoff and full jitter (base 1 s, cap 60 s), honouring `Retry-After`, and MUST NOT retry `400`, `401`, `403`, `413` unchanged.
- Producers SHOULD spool unsent events to local storage (bounded, oldest-first eviction) so a network outage or process restart does not lose signals.

## 9. Delivery semantics (JGR-R02, R06)

At-least-once. The receiver deduplicates on (`producer_id`, `event_id`) — the same rule as CloudEvents' `source` + `id` — and reports duplicates in the `202` body; retries therefore never inflate counters. Gaps in `sequence` per (`producer_id`, `thread_ref`) are surfaced as *possible signal loss* rather than hidden.

## 10. Clock skew (JGR-R07)

Receivers MUST reject events whose `occurred_at` is more than 5 minutes ahead of receipt time (`clock_skew`) and SHOULD record receipt time separately for ordering.

## 11. Versioning

`jgr` carries `MAJOR.MINOR`. A later minor version may add optional fields and event types. A receiver validates each event against the version it declares and, per JGR-R11, rejects top-level fields that version does not define; producers MUST NOT send fields from a newer minor version to a receiver that only supports an older one. v0.x is unstable.

## 12. Collector mappings (informative) and edge rules (normative)

Sources and verification status: [`../research/2026-10-20-sources.md`](../research/2026-10-20-sources.md).

**Edge rules (MUST):**

- The OTLP receiver accepts OTLP/HTTP with `http/json` and `http/protobuf` (gRPC is not offered on the serverless edge) and translates records into JGR events before validation.
- In L0 the receiver MUST drop identity attributes — `user.email`, `user.account_uuid`, `organization.id`, and any `*.email` — and MUST drop prompt/response content (`prompt`, `tool_input`, `tool_response`, `last_assistant_message`, assistant response bodies) even if a tool was misconfigured to send them.
- Collector setup (`javi init`, JD-C01/C02) MUST configure tools to keep content off: Claude Code without `OTEL_LOG_USER_PROMPTS` / `OTEL_LOG_TOOL_DETAILS`; Codex `log_user_prompt = false`; Gemini CLI `logPrompts = false` (its default is `true`).
- `session.id` / hook `session_id` become `thread_ref` only after hashing with a per-installation salt.

**Claude Code hooks → JGR:**

| Hook | JGR event |
|---|---|
| `SessionStart` | `session.started` |
| `SessionEnd` | `session.ended` |
| `SubagentStart` / `SubagentStop` | `agent.started` / `agent.stopped` (`agent_ref` from hashed `agent_id`) |
| `PreToolUse` / `PostToolUse` / `PostToolUseFailure` | `task.started` / `task.completed` / `task.failed` with `attributes.tool_name` only |
| `Notification` (`permission_prompt`, `idle_prompt`) | `attention.requested`, status `waiting` |
| `Stop` | `heartbeat`, status `idle` |
| `UserPromptSubmit` | `heartbeat`, status `working` — **prompt text discarded** |

**OTel token metrics → `usage_delta`:**

| Source metric | `type` value | JGR counter |
|---|---|---|
| `claude_code.token.usage` | `input` / `output` / `cacheRead` / `cacheCreation` | `input_tokens` / `output_tokens` / `cache_read_tokens` / `cache_write_tokens` |
| `claude_code.cost.usage` | — | `cost_usd` |
| `gemini_cli.token.usage` | `input` / `output` / `cache` / `thought` | `input_tokens` / `output_tokens` / `cache_read_tokens` / `reasoning_tokens` |
| `codex.turn.token_usage`, `codex.turn.cost_microusd` | per token kind | corresponding counters; cost ÷ 10⁶ → `cost_usd` |
| `gen_ai.client.inference.usage.*` (semconv main) | input / output / cache_read / cache_write / reasoning | same-named counters |

Semantic-convention versions are pinned per collector release because GenAI conventions are still *Development* status.

## 13. Error codes

`schema`, `too_large`, `privacy_forbidden_attribute`, `privacy_unhashed_identifier`, `privacy_encrypted_requires_l2`, `privacy_l2_requires_encrypted`, `status_required`, `usage_required`, `clock_skew`. Codes are stable; messages are not.

Receiver-side codes (depend on the token's project, so a producer cannot check them offline; added 2026-10-23, [ADR-0008](../../adr/0008-events-retention-and-ingress.md)):

- `project_mismatch` — `project_ref` is neither the slug nor the id of the project the ingest token belongs to.
- `privacy_class_not_allowed` — the event's `privacy_class` is above the class the project opted into (L0 < L1 < L2).
