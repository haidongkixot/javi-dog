S5c Codex CLI in `javi` (JD-C01, ADR-0016 Changes "S5c design" and "S5c design review"; consumes JD-C02): `--platform codex-cli` on `init`, `uninstall`, `status`, `hook` and `usage on|off` (Claude Code and Gemini CLI unchanged). `init` writes the stable launcher `~/.javi/bin/javi-hook` (+ `.cmd`) and appends javi's groups (timeout in seconds, `commandWindows`) to the project's `.codex/hooks.json`, keeping the user's groups in place; it never writes Codex approval state and warns about a git-tracked hooks file, a project `[hooks]` table and shell startup output. `uninstall` removes only javi's groups and lists the user's groups that shift. `status` reads project trust and hook approval from `config.toml` read-only and shows Codex session-start warnings first. `usage on --platform codex-cli` appends a marked logs-only `[otel]` block to `$CODEX_HOME/config.toml` (smol-toml parse before and after, refusal on any `otel` key or an uncovered proxy, backup 0600) and `usage off` removes exactly that block. The receiver adds `POST /v1/logs/codex-cli` (5 MiB cap, JD-C02 allowlist, sub-agent attribution, all-or-nothing spool); `/v1/logs` and `/v1/traces` stay unparsed sinks. New exports: `installCodexLauncher`, `installCodexHooks`, `uninstallCodexHooks`, `codexHookGroup`, `codexHookArgs`, `codexHooksInstalled`, `codexJaviGroups`, `codexHooksPath`, `codexLauncherPaths`, `codexLauncherScripts`, `unsafeLauncherPath`, `isCodexJaviGroup`, `codexHooksTracked`, `codexProjectConfigHasHooks`, `probeShellOutput`, `CODEX_HOOK_TIMEOUT_S`, `CODEX_SESSION_END_TIMEOUT_S`, `enableCodexOtel`, `disableCodexOtel`, `codexOtelBlock`, `codexOtelTable`, `codexHome`, `codexConfigPath`, `codexBackupPath`, `codexEnvRisks`, `parseDotenv`, `noProxyCoversLoopback`, `readCodexApproval`, `CODEX_LOGS_PATH`, `CODEX_BLOCK_START`, `CODEX_BLOCK_END`, `CODEX_EVENT_LABELS`, `CODEX_PROXY_ENV_KEYS`, `CODEX_HEADER_ENV_KEYS`, `CODEX_MAX_BODY_BYTES`, `codexTokenRecordInput`, `codexCostRecordInput`, `codexTokenEventId`, `codexCostEventId`, `codexThreadRef`, `hmacUuid`. Changed types: `PLATFORMS` adds `codex-cli`; `UsageConfig.codex` (`CodexUsageConfig`) is new; state adds `rememberSubagent` / `subagentParent` and Codex warning records (`CodexEnvWarning`); session refs may be `cx_…`. The bundle now also inlines `smol-toml` (listed in `THIRD_PARTY_NOTICES.md`).
