S5f privacy security-review fixes (ADR-0018 §8, §9, §11). M1: thread rows decrypt with an AAD built from the displayed row (its own `threadRef` and project slug) and the constant `x.javi.thread.identity` type; a moved identity object or a canary in a thread row shows "Can't verify…" and never marks the project checked (`ThreadIdentityLabel` now takes `projectSlug` and `threadRef`; `resolveThreadIdentity` for rows, `resolveProjectEvent` for the project label). M2: remembered key rows carry the signed-in user id; other users' rows are deleted, never loaded; the account menu binds keys to the session user, and every signed-out page (`SignInPrompt`, `/sign-in`, no session in the account menu) forgets every key. L1: "Remember on this device" is off behind `REMEMBER_ON_DEVICE_ENABLED = false` until the owner's CSP run on the signed-in project page; the UI neither offers nor mentions it. L2: API CSP adds `default-src 'none'; script-src 'none'`. L3: the key download URL lives 40 s; the key panel says a copied key isn't saved yet. L4: the L0 lowering warning says `javi init --privacy L0` deletes the machine's key. L5: per-project "checked" flags clear on sign-out, signed-out pages and class changes. L6: signing out waits at most 1.5 s for the device store. L7: the sentinel test drives the real page and server action. L9: the shown recovery key is never React state, and the paste-back field is emptied on every outcome.
